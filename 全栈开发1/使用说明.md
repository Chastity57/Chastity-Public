## 一、目录结构

```
全栈开发1/
├── main.go         ← 你的新后端（带 salt 的那版），原样放入，一个字节都没改
├── go.mod          ← 后端模块文件，原样
├── README.md       ← 原作者的项目说明，原样
├── AI_LOG.md       ← 原作者的 AI 使用日志（loginV2 里那份新版）
├── web/            ← 新增：登录网页（前端）
│   ├── index.html
│   ├── background.jpg   ← 页面背景图
│   ├── styles.css
│   ├── app.js
│   └── 调整背景.html     ← 调参小工具（拖滑块调背景位置，可删）
├── server/         ← 新增：桥接服务（把网页请求转成后端的终端输入）
│   ├── main.go
│   └── go.mod
└── 启动.ps1        ← 新增：一键启动（右键“使用 PowerShell 运行”）
```

首次启动时，桥接服务会在 `server/bin/` 下生成编译产物 `loginbackend.exe`（由原 `main.go` 编译而来），
这个目录可以随时删除，下次启动会重新生成。

后端的 `main.go` 取自你改过的 `Desktop\go\code\loginproj\main.go`（9/18 06:49 那版，多了 `salt` 字段、
`genSalt()` 与 `hashpass(salt, password)`），复制进项目后逐字节一致，可以自行核对：

```powershell
Get-FileHash .\main.go -Algorithm SHA256
Get-FileHash 'C:\Users\Chastity\Desktop\go\code\loginproj\main.go' -Algorithm SHA256   # 两个哈希应相同
```

根目录的 `预览-*.png` 是页面的实际渲染截图，其中 `预览-登录问候-分帧.png` 是登录问候动画的四个关键帧。

> 提醒（我没有改动你的后端，只做提示）：这版 `main.go` 里 `genSalt()` 定义了但没有被调用，
> 而且 `register` / `login` 调用 `hashpass` 时参数顺序写反了——函数签名是 `hashpass(salt, password)`，
> 实际调用是 `hashpass(password, s.salt)`。两处一起看，注册与登录算出的值仍然一致，所以功能正常；
> 但因为 `s.salt` 始终是空串，实际等价于 `sha256(密码)`，**盐目前没有真正参与运算**。
> 真要加盐：`register` 里先 `s.salt = genSalt()`，再写 `hashpass(s.salt, password)`，
> `login` 里改成 `hashpass(user.salt, password)`。改不改由你决定，我没有动它。

## 二、启动方式

```powershell
# 在 全栈开发1 目录里
.\启动.ps1
```

或者手动：

```powershell
cd server
go run main.go
```

启动后浏览器会自动打开 `http://127.0.0.1:8080/`，终端里会打印后端源码路径与接口列表。

如果 PowerShell 提示“因为在此系统上禁止运行脚本”而拒绝执行 `启动.ps1`，用这一行绕过即可
（只影响本次运行，不修改系统设置）：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动.ps1
```

如果只想看原作者的控制台版本，直接在 `全栈开发1` 目录运行 `go run .` 即可，行为与原来完全一样。

## 三、网页上三个按钮对应什么

| 网页按钮 | 发给后端的终端输入 | 触发的后端函数 | 后端返回的中文提示 |
| --- | --- | --- | --- |
| 1 注册 | `1` → 用户名 → 密码 | `loginact(1)` → `checkname()` → `register()` → `hashpass()` | 注册成功 / 该用户名已被注册 |
| 2 登录 | `2` → 用户名 → 密码 | `loginact(2)` → `login()` → `hashpass()` | 登录成功 / 密码错误 / 用户不存在 |
| 3 退出 | `3` | `loginact(3)` → `os.Exit(0)` | 退出登录（进程结束） |

登录成功（后端返回「登录成功」）时，网页会额外弹出一张问候卡片，显示「hello + 用户名」，
两部分依次从透明逐渐显示——这是纯前端效果，不改变任何后端交互。

## 四、为什么需要一个桥接服务

原后端是终端交互式程序：它用 `fmt.Scan` 从标准输入读数字和字符串，用 `fmt.Println` 把结果
打印到标准输出，用户数据存在内存切片 `userlist` 里。它没有 HTTP 接口，而题目要求
「后端代码不可更改」，所以网页不能直接调用它。

桥接服务（`server/main.go`）的做法是：

1. 用 `go build` 把原 `main.go` 编译出来，只读取、不修改它的源码；
2. 让这个程序常驻运行（这样 `userlist` 里的注册用户不会丢），把网页的表单内容写进它的标准输入；
3. 监听它的标准输出，把「输入你的用户名>」「输入密码>」这类提示和「注册成功 / 密码错误」这类结果解析出来；
4. 再用 JSON 返回给网页，于是按钮点击就等价于在终端里敲下 `1 / 2 / 3`。

对外接口（`/api/exit` 以外都是 POST）：

| 接口 | 请求体 | 说明 |
| --- | --- | --- |
| `/api/register` | `{"username":"alice","password":"123456"}` | 对应输入 `1` |
| `/api/login` | `{"username":"alice","password":"123456"}` | 对应输入 `2` |
| `/api/exit` | `{}` | 对应输入 `3`，后端 `os.Exit(0)` |
| `/api/status` | GET | 查看后端进程是否还在运行 |

返回体示例：

```json
{
  "action": 1,
  "actionName": "注册",
  "code": "register_success",
  "ok": true,
  "message": "注册成功",
  "output": ["注册", "输入你的用户名>", "输入密码>", "注册成功"]
}
```

## 五、界面说明

- 灰色主题：卡片、按钮、文字全部取自同一套灰色阶（`--g-50` 到 `--g-900`），卡片是半透明磨砂灰白，
  照片背景也被压成灰调，只有结果提示用了极低饱和度的绿/红来区分状态。
- 背景图：用你放进文件夹的那张照片 `B07E080C2B014D1D38B6B8D0ABDFD103.jpg`（1000×1416），
  已复制成 `web/background.jpg`。页面上它铺满整屏（`background-size: cover`），
  上面压了一层灰色遮罩（`grayscale(0.35) brightness(0.94)` + 深灰渐变）来维持灰色主题和文字可读性。
  想换背景：把新图片覆盖保存为 `web/background.jpg` 即可（原图那份仍在项目根目录，没有改动）。
- 背景图位置：检测到人物头部在图片的 x 0.48~0.65、y 0.21~0.38，居中的卡片正好会压住它，
   所以把整张图往左推了 **24%** 视口宽度、并整体放大 1.5 倍、向上偏到 20%：
  `--bg-shift-x: -24%`、`--bg-zoom: 1.5`、`--bg-pos-y: 20%`（都在 `styles.css` 顶部）。
  之所以要放大：`cover` 模式下图片宽度永远等于视口宽度，不放大就没有可平移的余量；
  平移量上限是 `(放大倍数 - 1) / 2`，超过会在边缘露出底色。
  想再左右挪一点，直接用 `web/调整背景.html` 那个滑块调参页（启动后访问
  `http://127.0.0.1:8080/调整背景.html`），拖到满意把三行数值填回 `styles.css` 即可。
- 登录框透明度：`--card-fill: rgba(250, 251, 252, 0.46)` + `--card-blur: blur(38px) saturate(125%)`
  （数字越小越透、模糊越大越"磨砂"）。按钮的透明度没有动，仍是 24% 白 + `blur(18px)`，
  所以按钮比卡片更"实"，层级反而更清楚。
- Liquid Glass 材质（按 `apple-liquid-glass-ui` skill 的规范调整，属于 Apple-inspired 的网页近似，不是官方组件）：
  - 登录卡片与问候卡片用的是同一套材质 token（`--lg-*`，见 `styles.css` 顶部）：
    斜向提亮层 `--lg-tint` + 半透明填充 + 背景模糊 + 细亮边（顶边 `--lg-stroke` 亮、底边
    `--lg-stroke-dark` 压暗，材质才有厚度）+ 安静投影 `--lg-shadow` 与顶部高光 `--lg-highlight`。
    登录卡片圆角 28px（`--lg-radius-xl`），问候卡片 34px（`--lg-radius-2xl`），内部控件 16px，
    同心：内层一定比外层小。
  - 玻璃只给「浮层 + 控件」：卡片本身、按钮、连接状态 chip、`kbd` 保留玻璃；
    卡片里的**内容面**（结果条、终端输出框）按 skill 的克制原则改成了不磨砂的浅色面，字号更清爽；
    输入框仍是轻玻璃（它是控件）。
  - 回退：`@supports not (backdrop-filter)` 时玻璃退成更实的半透明面（`--lg-fill-solid`），
    `prefers-reduced-transparency` 直接给实色，`forced-colors` 交给系统配色。
  - 深色外观下**不改变**你定的透明度（`--card-fill` 仍是 0.46），只把边框、高光、投影调沉一点，
    因为正文是深灰，面板必须保持浅色才读得清。
  - 按钮材质没动：仍是 24% 白 + `blur(18px) saturate(180%)`。
- 居中：`body` 用 `display: grid; place-items: center` 把登录卡片在窗口中双向居中。
- 圆形倒角：卡片 28px 圆角（`--radius-card`），按钮、输入框 16px 圆角（`--radius-control`）。
- 三个选项按钮：1 注册 / 2 登录 / 3 退出，只保留数字角标和名称，按钮上不再有说明文字；
  键盘按 `1`/`2`/`3` 同样有效，在表单里按 `Esc` 返回菜单。
- 实测对比度（按渲染出来的像素算）：卡片标题 6.2:1、按钮上的文字 11:1、卡片与照片背景 4.8:1，
  小号浅灰辅助文字在照片最暗处约 4.6:1（标称色算 5.2:1），整体达到 WCAG AA。
  卡片越透，小字越吃背景明暗；如果哪块小字看不清了，把 `--card-fill` 往 0.5 调、或把 `--ink-soft` 再压深一点即可。
- 按动反馈：按下瞬间按钮下沉 + 收缩（`translateY(1px) scale(0.97)`，160ms，
  `cubic-bezier(0.23, 1, 0.32, 1)`），松手后用同一条曲线回弹；切换表单时新视图从按钮方向轻微放大淡入（200ms）。
  遵循 `prefers-reduced-motion`，开启“减少动态效果”时只保留透明度与颜色变化。
- 目录里的 `预览-主菜单.png`、`预览-注册表单.png` 是页面的实际渲染截图；
  想直接把某个表单发给别人，可以用 `http://127.0.0.1:8080/?view=register` 或 `?view=login`。
- 登录问候卡片（登录成功后弹出，内容为「hello + 用户名」）：
  - 字体：直接用页面本身的系统字体（`system-ui / Segoe UI / 微软雅黑`），**不再使用行楷、舒体等风格字体**；
    两段文字同字号，只有用户名用 600 字重稍作强调。
  - 动画：全部只用透明度，没有任何位移、缩放、模糊或遮罩。
    卡片 0.32s 淡入（延迟 60ms）→ `hello` 用 **2 秒**匀速从全透明（opacity 0）拉到完全显示（opacity 1），
    延迟 0.4s，即 0.4s→2.4s → 用户名在 `hello` 走完的同一刻开始，用 **0.5 秒**匀速淡入（2.4s→2.9s），
    全部显示总共约 2.9 秒。
    实测曲线（用 WAAPI 把过渡 seek 到指定时刻，读浏览器插值出的 opacity）：
    hello 在 0.9s/1.4s/1.9s 分别为 0.250/0.500/0.750、2.4s 到 1.000；
    用户名在 2.5s/2.65s/2.8s 分别为 0.200/0.500/0.800、2.9s 到 1.000，都是标准直线。
    `getAnimations()` 里只有 opacity 一条，没有其它属性参与过渡。
  - 关闭方式：卡片上的「关闭」按钮、点击遮罩、或按 `Esc`；打开时背景内容会被 `inert`，焦点先落到关闭按钮，
    关闭后焦点回到原处。开启「减少动态效果」时只把节奏收紧（仍为淡入）。
  - 想调节奏：改 `styles.css` 里 `.greet__hello` 与 `.greet__name` 的 `transition-delay` / `transition-duration`
    （`hello` 是 2000ms、delay 0.4s；用户名是 500ms、delay 2.4s = 0.4s + 2s，所以用户名严格接在 hello 之后）。

## 六、已知限制（后端未改动带来的必然结果）

1. 后端把用户存在内存里，进程一退出（点“3 退出”）已注册用户就全部消失——这是原代码
   `var userlist []Users` 的设计，桥接层不做任何补救。
2. 后端用 `fmt.Scan` 按空白分词读取，所以用户名/密码里不能有空格，网页会提前拦住并提示。
3. 后端没有并发处理能力，桥接服务把请求串行化（同一时刻只执行一次终端交互）。
